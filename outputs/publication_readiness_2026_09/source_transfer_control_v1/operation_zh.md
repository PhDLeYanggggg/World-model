# 配对模态续训实验：运行与核验

## 这轮回答什么

上一轮 RGB 模型延长训练并降低学习率后，仅在完整训练集上出现小幅改善。
本轮补齐相同数据、参数量、采样顺序和训练预算的 coverage-only 对照，
再统一评价全部固定模型。要区分“优化改善”“跨录像预测有效”与“RGB 真有贡献”。
三者不是同一结论。

coverage-only 仍使用过去的运动/邻居几何、坐标变换和图像覆盖掩码，只把 RGB
置零，不是完全没有上下文。六条新续训共新增 48,000 步，另六条 RGB 分支来自
上一轮，经哈希校验复用，不能再次写成这轮重新训练。

## 数据边界

只用原 SDD train40 的完整、静止历史查询。训练排除 bookstore 后共 15,430 行；
bookstore 的 6,944 行仅供这轮固定源域诊断。它此前已经分析过，不是新鲜封存的
确认集。主任务仍为已批准的过去 8 点、未来 12 点；源域这轮采用 stride12，
预测范围为 +144 raw frames，不等同于主数据的物理时间。

主任务的模型选择、风险校准和最终确认数据仍关闭。未来标签只用于训练损失和
评价，不进入预测输入。没有新部署、Stage5C 执行或 SMC。

## 环境与恢复

项目路径：`/Users/yangyue/Downloads/World`。
使用 `.venv-pytorch/bin/python`，原生 arm64，Torch2.12.0，NumPy2.4.6。
CPU 计算线程4、inter-op线程1、DataLoader workers0，不用 x86_64 Conda。

运行命令见 [英文复现说明](reproducibility.md)。正常运行时检查：

- 私有目录 `data/stage_cvpr2027_experiments/source_transfer_control_v1/heartbeat.json` 中的 PID、时间和 step 是否推进。
- `training.log` 是否持续写入，检查点是否每200步保存。
- 如果进程仍在计算，不要再启动第二个相同输出目录的写入进程。
- 真正中断后重复训练命令即可恢复模型、优化器、采样器与随机状态；已完成分支会校验并跳过。
- 完成报告存在不代表核验结束，还必须执行固定评价、精确回放和分析命令。

训练前登记提交为 `71d0f520`，统计代码在新场景评分前另行冻结。配置或绑定
代码改变会触发审计失败；需要修复时保留原记录，不能静默覆盖历史结果。

## 如何读结果

`training_report.json` 记录新增训练，`evaluation.json` 记录固定模型评分，
`replay.json` 记录42次精确预测回放，`analysis.json` 记录配对检查、统计量及
完成后重跑的不可变性校验。`results.md` 展示全部比较，不只展示分数最好者。

2000次 bootstrap 的单位是同一个已探索物理场景中的7段录像。它不能支持
“跨独立物理场景已经泛化”的结论。三个训练种子也不能替代独立场景。

静止 easy 子集的基线误差为零，百分比退化没有定义，必须看增加的绝对误差。
“增加很少”不等于已经证明满足2%安全门槛。像素和历史归一化误差也不能称为米。
固定0.9分类概率门控只是保留的旧诊断，不是这轮重新校准的风险保证。

所有原始数据、图像、逐行预测和模型权重留在本地忽略目录。GitHub 仅保存代码、
配置、报告、轻量汇总指标和原创统计图。无关暂存数据不应随本轮提交。
