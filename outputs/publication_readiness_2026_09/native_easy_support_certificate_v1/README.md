# Why One Recording Cannot Pass With The Current Bank

I checked all 102 exposed recording-seed views using a simple
criterion, without another mixed-integer solve. When the diagnostic
may select any subset up to the original query cap, it can meet the
original risk rule exactly when at least one distinct, eligible
easy-row forecast has positive CV reference and a positive-harm
ratio no greater than 2%. One such action suffices. If every easy
action exceeds 2%, their strictly positive easy-budget excesses
cannot be canceled by non-easy actions or by wholly unknown rows.

The criterion matches all 102 previously checked solves: 99 feasible
views and three infeasible views. **All three failures are the same
recording**, not three independent sources. Each seed gives three
easy rows, with 27 distinct non-CV easy row-path options in total
per seed. The best option's harm is **23.925%** of its positive CV
reference in every seed, far above 2%. This is a lack of suitable
paths in this bank on that recording, not a failure to rank them.

The proof concerns risk feasibility, not gain over OLS4, mandatory
switch counts, or fixed multi-agent proposals. It needs observed
labels and cannot be used to certify a live policy. The CV identity
action does not create selected easy reference. No external data
or evaluation change.
