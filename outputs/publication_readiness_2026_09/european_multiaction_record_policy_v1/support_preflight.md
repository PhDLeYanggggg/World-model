# Support Ceiling Before the Decision Repair

Before any new policy optimizer update, check the fixed SOURCE inner-held
recording roster with the same label-aware bank oracle used on the148fitting
views. Keep all six contexts, all recordings, the original real-action/no-op
rule, easy event, masks, envelopes, references and2%requirements. Repeat the
original148fitting controls first. Count forecaster/context views once, not
three copies for cost-head seeds, since labels/actions are the same.

This preflight asks whether a full-roster pass is possible even for an oracle.
Report physical-only, physical+original-neural and neural-only banks. If a
held recording has no real known easy support or no feasible real easy anchor,
do not blame training alone, drop the recording or convert empty risk to zero.
Retain the original failure and identify that support ceiling explicitly.

The diagnostic uses future labels only offline and cannot create inference
features or actions. It reads only already-exposed SOURCE TRAIN inner-held
records, not independent selection/calibration/confirmation. A feasibility
result is not a causal learned result. Freeze this preflight/script before
running its full readout. Its outcome may change whether a costly optimization
can resolve the actual blocker; it does not authorize changing any metric.
